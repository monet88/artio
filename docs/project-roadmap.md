# Project Roadmap

## Current Phase

The repo is in a documentation-first stabilization phase. The product is already
implemented, so the roadmap now tracks documentation alignment, operational
clarity, and maintenance work rather than greenfield buildout.

## Active Priorities

| Priority | Area | Status |
| --- | --- | --- |
| 1 | Keep docs aligned with live code | In progress |
| 2 | Keep main app, admin app, and Supabase contracts synchronized | Ongoing |
| 3 | Keep model costs and premium flags mirrored between client and server | Ongoing |
| 4 | Keep build, test, and environment setup documented | Ongoing |
| 5 | Keep harness and product docs concise and discoverable | Ongoing |

## Near-Term Work

- Refresh product docs when app flows change.
- Refresh architecture docs when backend contracts or storage behavior change.
- Refresh code standards when toolchain or patterns change.
- Add missing operational notes only when they are justified by real workflows.

## Longer-Term Work

- Keep the changelog useful for operators and maintainers.
- Document release and deployment guidance in one place.
- Keep roadmap rows short and tied to observable code changes.
- Remove or merge redundant docs if they stop carrying unique value.

## Notes

This roadmap is intentionally small. It should remain a live coordination aid,
not a second spec.
